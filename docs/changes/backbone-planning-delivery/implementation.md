# Implementation scope and integration

The implementation follows the independently reviewed BB-PLAN-016 plan. Parallel
authors had disjoint ownership: planning contract/source register, seven planning
templates, validator/portability, and source CI. A separate test author added real
planning distribution/update checks. Root integrated entrypoints, adoption,
legacy distribution, source documentation and this delivery record.

## Delivered behavior

- PLAN-01..09 connect product goals, requirements and architecture to proportional
  delivery plans, typed items, tracker projections, run-specific packets, integration
  and evidence. P-S01..12 identify primary guidance and distinguish normative public
  scope, methods, project precedent and Backbone-owned rules.
- Seven original document templates include a hypothetical parallel implementation
  example with explicit unresolved decisions and no fabricated approvals/results.
- Canonical core and architecture handoffs reach planning. Legacy Copier always
  distributes the same guide, provenance, templates and existing pending JSON
  examples, while preserving project-owned records and native instructions.
- Governance JSON/schema inference is constrained to executable-owned engineering
  roots. Ordinary product fixtures no longer become governance because of names
  such as `examples`, `tasks` or `reviews`. Actual governance remains strict.
- Diagnostic paths use POSIX separators. Four additional LF rules protect existing
  byte-attested assets; a real autocrlf checkout now checks all 152 preserved entries.
- Source CI uses guarded dedicated local runners and no native artifact upload.
  Substantive checks remain; provisioning and native evidence are not assumed.
- Incoming review points have explicit dispositions; neutral export and optional
  profiles remain open, concretely specified follow-up work.

The rendered validator/schema/dependency tuple changes from the reviewed merged-base
digest `94f8f22f4dd66234d5048f2dee51c897fa7b9406694bf38ce44fef5186421120` to
`85519f27019364daf5ef22cc06ddc333811e5d5f0bc8fe3d98f77cd6c13ce152`.
The workflow explicitly retains that reviewed predecessor alongside the previously
approved identities. No candidate-supplied fingerprint, schema/state extension,

## Integration observations before frozen quality review

The first rendered planning test detected links to pending JSON examples that had
not previously been distributed to legacy consumers. Canonical include templates
were added for those three unchanged source examples; all five planning tests then
passed. An initial source-CI YAML scalar error was repaired before its six contract
tests and thirteen dependency tests passed. Earlier parallel reference/consumer
checks encountered the in-flight missing links; their results were not counted as
final evidence. The frozen quality run must qualify the integrated snapshot.

The actual merged-base validator against the integrated candidate passed, as did
the generated fingerprint check and committed-source whitespace preflight. These
observations do not replace the separate full quality run and independent reviews.
No Docker executable or native Windows host was available in this author environment.
Source runner labels describe required provisioning, not an observed fleet.
