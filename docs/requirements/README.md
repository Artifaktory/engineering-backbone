# Product requirements

Record this project's requirements and acceptance criteria here. Use the shared
document examples under `../templates/examples/` as starting points. Requirement
approval, implementation and verified acceptance are distinct states. Backbone's
historical delivery records are under `../changes/` and do not establish product acceptance.

Follow the [architecture contract](../agent-governance/architecture.md): every
requirement in a design scope needs an explicit architecture disposition and
links to the relevant decisions/views and verification, or a justified absence
of architecture impact. An unresolved required item blocks the affected gate.

Keep one authoritative source per requirement, with a stable ID, source revision
and responsible decision owner. Agents may propose derived requirements and
thresholds, but must preserve their draft status until the project's authorized
decision is recorded. Use the [project mapping](../templates/architecture/project-mapping.md)
and [traceability template](../templates/architecture/traceability.md) for information
not supported by the existing requirement JSON schema. Sphinx-Needs, other tools
or plain documents can represent the same semantics without changing this contract.
